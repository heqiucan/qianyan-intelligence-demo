## V3 核心链路的实测行为

1. 主导航只有“工作台、创意工作室、投放管理、效果与复盘”四个入口。
2. 新建营销活动后，携带正确活动进入创意工作室；生成结果明确标注回放。
3. “载入核对示例”只填入本地编辑区，不写入素材库。示例为“超大 1L 容量，保温 24 小时，现在只要 79 元。”。
4. 服务端将 1L、79 元识别为与当前资料冲突，将保温 24 小时识别为缺少依据。没有把“缺依据”直接等同于“为假”。
5. 可以打开每条提示的资料依据、对应字段与版本，再查看建议的修改前后。
6. 采用建议只修改可编辑草稿；重新核对后可保存为新素材版本，原素材保持不变。
7. 将容量改为 0.5L 后，规则正确识别为与 500ml 一致。
8. 人工确认通过服务端检查，确认后的具体版本带入投放草稿。
9. 保存并启动模拟计划后，完成模拟购买；订单保留正确的素材与计划关联，并能回看来源。
10. 缺少广告消耗时，界面说明未提供或暂不可计算；刷新后活动选择与成交记录仍在。

## 错误与状态验证

- **503 故障注入：**一次核对请求故意返回 503；局部错误可见，已输入文案保留，再次点击核对成功。该一次错误为验收预期。
- **过期响应：**延迟一份旧文案的检查响应，在返回前修改输入；旧响应不覆盖当前草稿的检查结果。
- **未保存离开：**修改文案后尝试进入投放管理，取消确认框后停留在原页面，输入保持；点击素材卡片“用于投放”接受离开时只出现一次确认，投放草稿继续预选对应已确认版本。
- **原 V2 故障恢复：**待办状态保存的一次 503 注入仍通过，弹窗保留输入、重试后正确保存。

## 重复运行

分别用独立终端启动对应隔离端口；以下示例为 V3，不能将 `DEMO_DATA_DIR` 改成用户 `data/`：

```powershell
$env:DEMO_DATA_DIR = 'tmp/v3-acceptance/data'
$env:MODEL_PROVIDER = 'replay'
$env:DEMO_ACCESS_TOKEN = ''
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8022
```

另一终端运行：

```powershell
node scripts/browser_v3.cjs
```

原 V2 两路线分别使用上表中的隔离端口和数据目录，然后执行对应脚本。测试需要本机捆绑的 Playwright 与 Edge，脚本支持 `PLAYWRIGHT_MODULE` 指向其他已安装的 Playwright。
