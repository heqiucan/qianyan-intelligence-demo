# 错误与状态分类

核对：2026-11-23。这里只记录已有语义，不新增统一错误编号或改变 API。HTTP 状态相同可能代表不同原因，操作必须同时检查 detail 与版本字段。前端传输行为以 `frontend/src/api.ts` 为准；业务状态以下列源码为准。

## 通用错误类别

| 类别 | 常见来源 | HTTP/浏览器表现 | 前端处理 | 重试规则 |
| --- | --- | --- | --- | --- |
| 输入校验 | Pydantic、字段、文件格式、日期 | 400/422 或页面字段错误 | 保留输入，指出字段和修正动作 | 修正后重试 |
| 访问或请求范围受限 | demo token、访问限制 | 401/403等 | 显示访问或配置入口，不循环重试 | 用户处理后重试，不能将设备权限映射成HTTP403 |
| 版本冲突 | 商品、货盘、队列、规则、计划 | 409 | 阻止继续，刷新并重新核对快照 | 不能盲目重试 |
| 幂等冲突 | request_id 对应不同 payload | 409 | 刷新列表核对结果 | 更换请求前先确认服务端结果 |
| 资源限制 | 文件大小、数量、并发、时长 | 413/422/409 | 保留可编辑输入，明确上限 | 修改资源后重试 |
| 外部/模型失败 | 连接、配置、限流、格式 | 依实际接口返回，可能429/502/504/422 | 保留原内容和任务记录，给出对应操作 | 不自动换模型；具体内部重试取决于现有实现，UI不盲目重复提交 |
| 设备/浏览器能力 | 摄像头、麦克风、媒体解码、对象地址 | 权限拒绝或本地异常 | 给授权/设备/格式操作建议，释放迟到资源 | 用户重新选择或授权 |
| 任务中断/取消 | 服务重启、显式取消、页内定时停止 | 各自独立状态 | 保留记录，按模块显示继续/重建入口 | 页面隐藏不等于后台Agent中断；浏览器定时与后台任务分开判断 |
| 数据缺失 | 无订单、无消耗、无日期粒度 | 正常响应中的缺失状态 | 显示“未提供/不可计算”，不显示假 0 | 补足数据或改变范围 |
| 未接入能力 | 平台推流、真实弹幕、支付、商品卡 | 页面边界提示 | 留在相关操作位置，不能伪装成可用 | 需要另行产品与权限决策 |

## 重要业务状态

| 对象 | 状态/规则 | 允许的下一步 |
| --- | --- | --- |
| Agent task | queued、running、waiting_input、waiting_review、completed、failed、interrupted、cancelled | 按状态创建、补充、继续、审阅、完成或取消；完成后依据变化可重新打开 |
| Demand run | queued、running、paused、interrupted、failed、waiting_review、waiting_input、completed、cancelled | 以 `frontend/src/features/demand/types.ts` 和 `backend/demand_tasks.py` 的控制规则为准；pending/confirmed/excluded 是结果行状态，不是运行任务状态 |
| Creative | draft、approved 等 | 编辑新版本、核对、确认；确认后可进入计划 |
| Plan | draft、running、paused、ended | 核对、启动/暂停/结束、创建调整；计划使用素材和商品快照 |
| Live session 货盘状态 | draft、ready、archived | `frontend/src/features/live/types.ts`、`backend/live.py`；确认货盘不等于开播 |
| Live workspace 模拟运行 | idle、running、paused、stopped | `backend/live_workspace.py`；启动/暂停/停止独立于货盘状态，启动需确认版本 |
| 本地媒体资源 | 文件/设备/播放器各有状态，无统一枚举 | 以 `frontend/src/features/live/LivePreview.tsx`、`frontend/src/features/live/AudioMixer.tsx`、`frontend/src/features/live/speech/SpeechPlayer.ts` 为准；分别验证暂停/释放 |
| Report | 保存后的快照，不假定有 `saved` 枚举字段 | 查看、打印、另存新报告；后续数据不改写历史快照 |

前端超时/网络错误的 `ApiError.status` 中，0表示连接失败，499表示本地停止等待，504可能由本地超时产生，不能都说成服务器返回。携带 request_id 的模糊失败保留请求标识，明确的400/401/403/404/413/415/422校验失败按现有代码清理重试缓存；409需要先核对冲突，不机械重试。

## 文案要求

- 错误文案说明发生了什么、用户能做什么、是否需要先刷新；不指责用户。
- `未提供`、`不可计算`、`有效的 0` 不混用。
- 模拟、回放、未接入和人工确认状态要在业务相关位置保留，但不把内部实现细节塞进主操作区。
- 服务器已可能执行的超时请求不能写成“肯定没有保存”；应提示先刷新核对结果。
