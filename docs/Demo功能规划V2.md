# 浙衍 AI Demo 功能规划 V2

日期：2026-11-10。状态：用户确认后已实施前两阶段的主要业务流程。本文保留完整设计目标；实际交付与限制以 README.md、docs/V2验收记录.md 为准，P1/P2 仍为后续范围。

用户已确认：主要用户为电商商家、品牌运营，重点是营销、广告投流、成交与优化。仍沿用黑紫色工作台；AI 默认演示回放，广告和支付模拟。真实模型、抖音账户及支付尚未接通。

## 1. 产品目标与取舍

帮助运营人员完成“明确推广目标 → 制作内容 → 配置投放 → 获得成交 → 发现问题 → 调整并观察 → 汇报结果”。

V2 的目标是使每次重要操作都能产生可保存、可追溯、可继续处理的业务结果。点击按钮、播放动画、随机刷新数字不等于完成业务交互。

保留商家自营视角。代运营客户商机、合同提成、服务费和回款不进入主流程。直播可以后续作为独立推广场景扩展，不在当前商品推广页中放一个不可执行的直播开关。

## 2. 同事截图中可参考的内容

截图直接可见：经营总览、商家项目、直播与转化、成交跟进、商机管道、异常督办、收益与结算、交付报告等菜单，以及收益与结算页中的金额卡片、结算明细、待核对状态、手工回款登记、成本说明和报告入口。只能确认这些界面内容，不能据此确认其他页面或后台流程已实现。

| 对方功能或设计 | 我们的取舍 | 对应业务价值 |
|---|---|---|
| 经营总览 | 借鉴可点击指标、目标进度和待办；指标进入带筛选的明细 | 老板能看结果，运营能继续处理 |
| 商家项目 | 转换为营销活动：商品、目标、预算上限、周期、素材、计划、结果 | 多个活动各自有完整上下文 |
| 直播与转化 | 借鉴转化漏斗；先落实广告点击、商品访问、模拟购买 | 定位在哪一步流失；直播独立延后 |
| 成交跟进 | 转换为订单、买家历史、新老客识别及后续退款记录 | 看清推广带来的成交质量 |
| 商机管道 | 不建设 B2B 销售商机；用活动进度与转化漏斗承接 | 防止产品偏离电商推广 |
| 异常督办 | 新增异常待办、证据、处理动作和复查 | 让问题进入可执行流程 |
| 收益与结算 | 借鉴金额口径分离与明细追溯；后续做活动投入产出 | 分清销售额、广告消耗、退款及已录入成本 |
| 交付报告 | 转换为活动复盘报告，记录事实、调整与待观察项 | 向老板说明本轮做了什么、结果如何 |
| 悬浮 AI 助手 | 后续做当前活动上下文助手，优先嵌在诊断与操作旁 | 直接形成草稿；先不增加无任务关联的聊天窗 |

截图的服务费、合同提成、已确认收入和实际回款属于代运营业务，不能当作电商商品成交额；“预计项目贡献”也不应直接改名为净利润。

## 3. 已实现基础与明确欠缺

基于当前 `frontend/src/App.tsx`、`backend/main.py`、`backend/model_adapter.py` 和 README 核对。

| 范围 | 已有能力 | V2 主要缺口 |
|---|---|---|
| 活动 | 新建、切换、商品快照、本地保存 | 目前主要输入只有名称；缺目标、策略、活动详情和准确进度 |
| 商品 | 编辑、版本、图片/已有视频上传 | 只有一个商品；缺多商品库与资料来源字段 |
| 创意 | 两组回放、人工编辑、新版本、确认、PNG 导出 | 缺单组重新生成、版本对比、策略配置；固定通勤/容量方向 |
| 投放 | 创建预算/周期草稿，启动、暂停、恢复、结束 | 缺草稿修改、计划调整版本、复制和消耗进度；日期目前不驱动调度 |
| 成交 | 广告预览、商品页、测试买家、模拟付款、来源追溯 | 缺更完整筛选、购买确认与数量、退款等后续流程 |
| 数据 | D0 与现场分开、指标计算、CSV | 缺一致的下钻筛选、运营可复用的数据批次；现场无曝光和消耗 |
| 优化 | 事实/假设/缺失信息、采纳生成素材草稿 | 缺复盘历史入口、建议处理状态、计划调整草稿、观察任务 |
| 支撑 | 持久化、操作记录、部分幂等保护、错误提示 | 缺统一状态交互、异常待办、快照报告 |

需先修正的现有表达：进度条不能固定把商品算完成、把优化固定为未完成；计划仅存草稿不能直接表示投放已完成；“本次互动”实际包含此前保存的本地互动，需改名为“现场互动记录”，并提供可见范围；“生成 V2”应显示实际下一版本号。

## 4. 功能模块与交互约定

以现有六个模块为主，增加异常待办与复盘报告。新增能力可先以抽屉、页内标签、操作入口呈现，业务完整后再决定是否独立为菜单。

优先级：P0 为本轮完整演示必须做；P1 为主流程验收后增强；P2 依赖外部资源或独立业务场景。

### M1 经营工作台与营销活动（P0）

- 活动表单：名称、商品快照、受众假设、主推卖点、计划周期、活动预算上限、内部观察目标。平台推广目标仍为商品成交，新客数是内部观察项。
- 活动详情：展示策略、商品版本、关联素材与计划、结果和待办；切换活动时全部区域切换，刷新恢复选中项。
- 活动策略修改产生版本；已确认素材与投放不随之被覆盖。
- 指标卡可点击：点击订单进入对应活动/数据来源/时间的订单；点击消耗进入相同范围的消耗明细。
- 进度由有效记录推导，点击步骤进入具体对象和未完成事项。允许在活动运行时继续迭代素材，不能把迭代误当作退回起点。
- 验收：新建活动并填写目标后，刷新仍可见；保存计划草稿与实际模拟启动显示不同进度；跨页筛选保持一致。

### M2 商品与品牌资料（P0 保强，P1 扩展）

- P0：资料完整性提示、卖点依据/来源、保存前确认差异、未保存离开提醒、上传错误与重试。
- 商品改价后提示“新建活动使用新版；既有活动仍引用旧快照”，并支持查看两者差异。
- P1：多商品列表、新增/编辑/归档、搜索；创建活动选择商品。第一步不建设仓库、采购或完整库存系统。
- 验收：修改价格不改旧订单和旧计划；引用中的商品归档后仍可查询历史。

### M3 营销与创意工作台（P0）

- 可选择受众假设、表达角度、内容格式和语气；回放模式采用支持这些选项的明确模板，不声称可以自由理解所有输入。
- 单独重新生成某一组、编辑并保存新版本；保留另一组与原人工编辑结果。
- 按创意系列收纳版本，查看文案和商品依据的版本差异。
- 确认前展示已知字段冲突和缺失依据；定位到需要修改的字段，规则校验不称为全面合规审查。
- 海报模板选择、实时预览、PNG 导出；已有视频预览与脚本编辑延续首版边界。
- “用于投放”带入确切版本；草稿不能直接启动广告计划。
- 验收：修改一组不会覆盖另一组；已确认版本修改后重新确认；导出与预览一致。

### M4 广告投放中心（P0）

- 计划详情：素材快照、计划总预算、周期、状态、执行记录、对应数据集的消耗和成交。预算配置值与消耗分开。
- 草稿支持编辑、复制；复制生成独立新草稿，不复制历史转化。
- 对运行计划调整预算或周期：先产生调整草稿，展示前后值、适用范围和生效方式，人工确认后写入新的计划配置版本。
- 更换素材建立后继计划，保留原计划与原素材关联，避免旧数据被重新解释。
- 批量暂停先预览选中的计划和影响，逐项返回成功/失败；结束操作有明确确认，历史数据保留。
- 配置需校验预算与日期。P0 继续明确“人工模拟执行”；若日期已过或与当前时间冲突，提示并阻止不合理的新启动，不假装已有定时投放能力。
- 新增“预设投放场景”入口：选择固定的演示数据批次，预览字段、窗口和关联对象后载入。支持有点击无成交、消耗接近上限等演示情境。
- 场景载入生成独立模拟批次，关联真实存在的演示计划，具有曝光、点击、消耗、订单等一致依据；展示为模拟场景，不能把 D0 的历史计划 ID 当作现场可操作计划。
- 相同提交不重复入账；重复演示创建新批次。手动购买留在现场互动范围，不与场景批次混算。
- 验收：调预算会改变配置和记录，不直接产生更多订单；暂停后拒绝新模拟执行；选择场景前能看到将新增的数据。

### M5 成交与获客分析（P0；退款与成本为 P1）

- 统一活动、计划、数据来源、日期筛选；未提供相应日期粒度的数据禁用日期筛选并说明。
- 明细可下钻：指标 → 对应订单/消耗/买家 → 具体活动、计划、素材和配置版本。
- 漏斗只显示当前来源实际具备的步骤。消费者广告预览/商品浏览不能冒充真实平台曝光；缺失步骤显示缺数据，不填零。
- 区分支付订单、去重买家、新客、老客、未知历史及识别覆盖率；重复购买增加订单但不重复增加新客。
- 显示没有匹配消耗时 ROI 不可算；不能拿另一个数据集的消耗补上。
- P1：模拟部分/全额退款，退款额度不能超过可退金额；保存原支付和退款流水，增加退款后净成交口径。历史首次购买事实不因退款而静默重写，其他获客口径另行展示。
- P1：登记商品、履约、平台费用和广告成本，估算“已录入成本口径的活动贡献”；明确漏项，不称为公司净利润。
- 验收：筛选范围在卡片、表格、下钻、导出中一致；重复买家及未知历史显示正确。

### M6 AI 优化与观察（P0）

- 保留事实、假设、缺失信息，增加历史复盘列表及统计窗口。
- 建议可采纳、暂不采纳并填写理由；采纳后有结果对象链接，重复采纳同一动作不重复生成草稿。
- 两类结果：新素材草稿、计划配置调整草稿。动作都先核对再确认，回放或真实模型均无独立花费权限。
- 自动建立观察任务，记录调整前版本、调整后版本、数据来源、窗口和观察指标。
- 状态：待处理 → 草稿已创建 → 待确认 → 观察中 → 已复盘；也允许暂不采纳。
- 同源同口径且窗口明确才进行前后对比；不满足时显示缺少哪些数据。结束观察不等于效果变好。
- 调整后不自动填充改善数字；后续模拟数据必须经明确载入，允许改善、无变化或恶化。
- 验收：复盘可以重新打开；能从建议找到新版本/新计划；数据不足时保持待观察。

### M7 异常与待办（P0）

- 两类事项：业务待办（资料缺失、素材待确认、计划待确认），数据异常提示（用户设定的消耗阈值达到但无成交、预算接近耗尽等）。
- 数据异常必须有来源、观察窗口、规则版本、相关样本量和阈值。没数据或样本不足优先显示“待补数据”，不直接宣布投放失败。
- 每条包含原因、证据、影响对象、处理动作、备注；支持查看明细、创建调整草稿、暂停模拟计划或标记暂不处理。
- 状态：待处理 → 处理中 → 待复查 → 已解决/已忽略；忽略需理由。
- 同一对象同一规则同一窗口不重复生成任务。采纳建议不直接关闭异常；重新检查或人工附理由确认后才关闭。
- 单人版先只用当前运营身份记录操作；多人分配和角色审批延后。
- 验收：完成动作后能追溯关联记录，重新检测同一问题不无限增加红点。

### M8 活动复盘报告（P0 简版，P1 增强）

- 选择活动、数据来源和观察窗口，自动汇总目标、素材、计划、投入、成交、新客、异常和调整记录。
- 运营可编辑结论和下一步行动；系统事实与人工判断分区。
- 生成报告快照，保留生成时间、数据批次、指标口径和模拟/回放标记；后续变化需生成新版，不能悄悄改旧报告。
- P0 支持报告预览及浏览器打印/另存 PDF；明细 CSV 延续现有功能并跟随筛选。独立高质量 PDF 排版放 P1。
- 验收：报告每个关键数字可追溯到对应范围；刷新后可继续查看旧报告；新订单不修改已保存报告。

### C1 消费者演示（P0）

- 路径：广告预览 → 商品详情 → 数量与模拟买家选择 → 订单确认 → 模拟付款 → 结果 → 后台订单。
- 返回或取消可保留表单但不产生支付成功；重复付款按钮只保存一笔订单。
- 金额使用绑定的商品快照和确认数量，由后端计算。前端改金额不能改变后端成交数值。
- 计划状态变化时重新校验；暂停后不能新增模拟成交，已有记录仍可查看。
- P1 再增加退款演示，避免同时扩展真实支付、物流和完整商城。

## 5. 通用交互标准

1. 所有操作都有可见的处理中、成功、失败状态；失败保留输入并允许重试，长操作不冻结无关区域。
2. 所有按钮明确其结果对象；只提示“操作成功”却不改变数据的不算完成。
3. 重要入口携带活动、计划、素材版本和筛选上下文，返回时保留列表条件。
4. 空状态说明缺什么并提供下一步；按钮禁用说明原因；没有未实现功能的假开关。
5. 编辑离开提醒；结束计划、批量变更等有影响预览；不可逆操作优先归档和保留记录。
6. 保存后刷新、关闭再打开仍可恢复；幂等保护覆盖可能重复创建业务记录的提交。
7. 继续维持商品、素材与计划快照；变更留下新版本，不能篡改历史。
8. 窄屏能打开详情、填写表单并关闭弹窗；键盘可操作；减少动画设置有效。
9. AI 回放、场景模拟、现场记录、未来导入数据使用明确来源标签，导出仍保留。
10. 日志不替代待办；设置中的静态介绍不伪装成可配置能力。

## 6. 数据与计算边界

至少保留三种独立范围：固定 D0、现场互动记录、主动载入的模拟场景批次。跨来源只能并列查看，不能无说明地合并。

经营指标是本产品内的统计约定，不代替平台官方结算或财务账。退款与成本功能启用时先明确范围：

- 支付金额与退款金额分别保留；净成交金额为所选订单集合的支付金额减对应退款，说明退款统计截止时间。
- 支付 ROI 使用同一来源与窗口的支付金额除广告消耗；退款后口径单独命名，不覆盖原指标。
- 已录入成本口径的活动贡献，按同一范围净成交金额扣除已录入商品/履约/平台/广告成本计算；成本缺失不得当零。
- 订单成本与退款关联需要单独记录实际损失、返还和成本调整，不能只按退款金额比例假定所有成本返还。
- 买家身份、首次购买、未知历史处理保持可解释；新客指标不自动推断广告增量。

规划需要新增或扩展的业务记录：活动策略版本、计划配置版本、调整草稿、数据批次/消耗明细、异常任务、观察任务、报告快照；P1 再加多商品、退款记录与成本记录。数据表和接口形式在进入实现时细化。

## 7. 两条演示路线

### 路线 A：完成一次商品推广

建活动并设置目标 → 选择卖点和受众假设 → 生成并编辑单组创意 → 对比和确认 → 建计划并核对模拟启动 → 消费者确认数量和模拟购买 → 后台订单、新客和来源更新 → 保存活动报告。

讲解重点：每一步的结果进入下一步；订单确实改变统计；原素材版本可追溯。

### 路线 B：处理一次投放问题

为演示计划明确载入“有点击无成交”的模拟场景批次 → 异常卡显示阈值、窗口与依据 → 查看详情 → 生成回放诊断 → 创建新素材或计划调整草稿 → 人工确认 → 建立观察任务 → 查看缺失数据或载入明确的后续模拟批次 → 复查异常 → 保存报告。

讲解重点：调整是一个可记录的动作；修改预算不会自动导致效果改善；无后续数据时留在观察中。
