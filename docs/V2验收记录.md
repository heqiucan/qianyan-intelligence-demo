# V2 业务 Demo 验收记录

日期：2026-11-10。范围：已确认规划的前两阶段，商家营销、模拟投流、成交、异常处理、优化观察和报告。真实模型、广告账户及支付仍未接入；没有公开网址。

## 已实现范围

- 活动策略字段与版本、保存后继续创意、业务记录驱动进度、指标下钻。
- 商品资料来源、保存差异核对、未保存离开提醒。
- 创意按系列管理、单组重生成、版本比较、经典/极简模板实时预览、PNG 导出、人工确认。
- 计划草稿编辑、复制、人工启动、暂停/恢复/结束、批量暂停逐项反馈、调整草稿及前后值确认、配置版本冲突保护。
- 独立模拟场景预览/载入、三种来源隔离、计划与日期筛选、成本指标和识别覆盖、订单/消耗依据及同范围 CSV。
- 消费者数量、确认页、服务端金额、付款幂等和订单追溯。
- 异常扫描去重、证据、处理状态/备注/历史；复盘历史与暂不采纳，素材或计划动作互斥。
- 观察任务开始、同源后续数据复查，缺数据时保持观察；报告不可变快照、人工结论、打印/另存 PDF。

## 运行与复测

本机 8000 服务已重启到新版，检查了健康接口、新增场景 API、状态 API、实际浏览器工作台及八项导航；原有业务数据保留。桌面快捷方式继续使用同一 `start-demo.cmd`，服务就绪后打开浏览器，重复运行复用现有服务。

浏览器测试需要本机 Playwright 与 Edge；脚本默认使用本机捆绑运行库，其他环境可用 `PLAYWRIGHT_MODULE` 指向可用模块。先在两个独立终端分别启动测试服务，再运行对应脚本。不要将测试服务指向用户 `data/`。

```powershell
# 路线 A 的隔离服务
$env:DEMO_DATA_DIR = 'tmp/v2-acceptance/data'
$env:MODEL_PROVIDER = 'replay'
$env:DEMO_ACCESS_TOKEN = ''
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8020
# 另一个终端运行：node scripts/browser_v2_core.cjs

# 路线 B 使用另一终端、另一数据目录和端口
$env:DEMO_DATA_DIR = 'tmp/v2-feedback-acceptance/data'
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8021
# 另一个终端运行：node scripts/browser_v2_feedback.cjs
```
