## 产品定位与已经确认的边界

这是营销获客与广告投流的可运行业务 Demo，前端、后端和数据库都已具备。独立官网用于介绍产品，运营工作台本身也有前端，不要把工作台称为“只是后端”。

有两个独立场景：

1. **直播电商营销**：商品依据、营销活动、创意、模拟投放、模拟购买、数据分析、优化与报告。
2. **医美获客内容**：机构知识库、带引用的内部 FAQ / 预约说明草稿、人工审阅与导出。目前没有咨询、预约、到店 CRM。

用户尚未提供真实机构和品牌资料。示例是虚构的，不能把示例当成资质、真实业绩或真实医疗结论。医美人工确认不等于医疗广告审批。

用户重视可以看见、可以交互的效果；解释功能时要告诉他从哪里点、接下来做什么。用户说“先规划 / 先回答 / 别改”时不修改；“开始吧”是执行已讨论的阶段，不是自动实施所有远期建议。

## 当前三条使用链路

### 商品营销

商品事实 → 新建活动和策略 → 生成 / 修改创意 → 查看规则核对和依据 → 人工确认素材 → 建立计划 → 人工确认模拟启动 → 体验商品页与模拟购买 → 查看订单来源 → 同源分析与复盘 → 新版草稿 / 观察 → 报告快照。

这是单店、单商品 Demo。没有真实抖音广告账户、真实付款或真实直播接口。模拟计划也不会自动花费预算。

### 知识库与 RAG

选择场景和资料空间 → 导入 TXT / Markdown / 文本型 PDF 或粘贴文字 → 核对解析、适用范围和有效期 → 人工标记可用 → 输入关键词检索 → 查看命中段落、页码和版本 → 基于依据生成草稿 → 修改保存 → 人工确认 → 导出或转入活动。

- 本地 jieba 分词 + SQLite FTS5/BM25，属于关键词检索式 RAG。
- 没有向量数据库、混合检索或扫描 PDF OCR。
- 历史脚本不能单独充当商品或机构事实依据。
- 普通 RAG 示例导入后需要人工核对；Agent 预置示例在独立、明确虚构的资料空间准备，不覆盖原资料。
- 内容按记录标注真实模型或摘录回放模式；引用存在并不自动保证每句话正确。

### 营销任务 Agent

增长工作台 → “交给 AI 处理” → 选择医美 FAQ 或直播讲解稿 → 输入目标，选择虚构示例或自己的可用知识库 → 查看实际检索、读取、缺口判断、生成 / 编排和检查事件 → 补充要求或重试 → 保存草稿 → 人工确认 → 标记任务完成。

- 自定义 Python 有界工具执行器；没有引入 LangGraph / LangChain。
- 使用结构化模型输出选择有限操作，服务端校验后执行；不要声称已完成模型原生 `tool_calls` 集成。
- 医美 FAQ 是带引用的内容生成；直播稿目前由智谱选择事实原文，再由服务端组合中性衔接，界面标为“智谱选取依据 · 原文组合”。
- 当前限制：每轮最多 7 次模型调用、12 步、2 次搜索，最多 5 轮；240 秒预算在步骤边界检查，不等于强制终止外部请求。
- 有持久化任务、执行记录、继续 / 重试 / 取消。服务重启后中断任务需手动继续，不偷偷重发。
- 同一业务库按单实例、单 worker 运行，不应同时启动多个写入相同库的服务。
- 不自动发布、不调用真实投流、不扣款。
