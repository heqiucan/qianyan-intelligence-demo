# 行业知识库与关键词 RAG：首个里程碑

日期：2026-11-11。范围：资料导入 → 审核 → 中文关键词检索 → 引用预览 → 智谱/回放草稿 → 人工核对、修订、确认、导出。官网、原首页和八个一级功能入口保留。完整医美 CRM 与直播经营模型没有在这次实现。

## 可演示功能

入口一：商品与品牌 → 知识库与 RAG。入口二：营销与创意 → 行业知识草稿，两者查看同一批持久化资料和草稿。

1. 选择医美获客或直播电商；各有一个内置虚构演示空间。支持建立新的机构/品牌资料空间。检索严格选择一个空间和一个适用范围，不做跨机构或跨场景混合检索。
2. TXT、Markdown、文本型 PDF 导入；也可直接粘贴。文件提取在服务端本机完成，不发送文件至模型。不保存原始二进制文件，保存提取的页文本与元数据。支持 UTF-8/GB18030 文本；最大 5 MB、50 页、12 万字。加密/空白 PDF、超限与不支持格式给出错误；没有 OCR，部分空白页会提示。
3. 导入后为待审核。设置资料类型（事实、审核要求、历史脚本）、内部/抖音渠道参考、起止日期。人工核对后标记可用。有效期按 UTC 日期，结束日期当天有效。已过期、未生效、待审核、归档内容不参与生成。
4. 更新保存为新版本并重新审核；旧内容和草稿引用快照保留。归档取消检索资格。没有永久删除资料功能。
5. 本地中文分词、领域词典、全文索引和 BM25 排序。查询与索引使用同一套规则；保留中英文、数字、规格等词项。最多展示 6 段、每文档最多 2 段；候选范围先过滤再排序限量。声明和单独标题不作为可回答片段。
6. 展示来源标题、版本、段落或 PDF 页码、命中词与原文。关键词分数不是事实置信度，也不表示语义问题必有答案。无命中或仅命中历史脚本时不调用模型。
7. 生成前校验本次检索签名；资料变化后必须重新检索。生成期间不持有 SQLite 写事务，保存前再次核对来源。模型失败保留原内容，无自动付费降级或自动重试。
8. 草稿每段绑定有效引用 ID。服务端拒绝伪造引用、空引用和仅以旧脚本支撑事实的段落。历史脚本允许作为结构参考。这里校验的是引用完整性，尚没有自动蕴含/事实正确性判定。
9. 模型模式显示智谱实际型号；回放模式直接摘录检索原文并明确显示“未调用模型”，不伪装为实时推理。模型只接收任务与命中的片段。
10. 编辑并保存增加草稿版本、清除原确认状态；逐段核对后勾选确认。导出 Markdown 包含正文、来源和原文快照。更新/失效来源提示重新生成；旧确认记录保留但不表示当前仍可使用。

## 医美与直播的边界

- 医美定位为内部资料与内容核对。没有诊断、治疗方案选择或临床适用性判断；知识审核和草稿确认不是医疗广告审批。发布条件仍需按具体内容、资质、渠道核对。
- 直播资料不提供当前价格、库存、优惠和经营指标。当前版本把缺失事实列为待核实，不从旧脚本推断。多 SKU、场次与真实投流数据尚未接入。
- 资料空间是单运营员 Demo 的内容隔离，不是企业多租户授权。没有对资料上传做患者个人信息自动识别或脱敏，请使用演示或已去标识化资料。
- 未接入向量检索、重排序模型、OCR、语音转写、自动发布、广告扣费。关键词词典不做医疗项目间的自动等价替换。
- 资料中存在来源并不代表真实或允许宣传，引用也不保证模型完全正确；已保留人工核对环节。

## 上游参考与本项目实现

| 组件 | 使用版本 / 许可 | 用法 |
|---|---|---|
| [SQLite](https://github.com/sqlite/sqlite) / [FTS5](https://sqlite.org/fts5.html) | 当前 Python 运行时 3.53.1，Public Domain | 全文倒排索引，内建 BM25；按升序取最相关结果，不把负分展示成置信度 |
| [jieba](https://github.com/fxsjy/jieba) | 0.42.1，MIT | 搜索分词、统一词项处理、项目领域词典 |
| [pypdf](https://github.com/py-pdf/pypdf) | 7.0.1，BSD-3-Clause | 本机提取 PDF 文字和页码，不进行 OCR |
| motion-site-tools | 项目已有 MCP，product-ui | 读取设计参数与 CoastSignal 参考，保留原有黑紫配色和组件；没有升级 React 或套用模板数据 |

没有复制完整 Dify/RAGFlow 系统。资料状态、场景空间、有效期过滤、版本快照、请求幂等、智谱适配、人工核对 UI 都在当前 React/FastAPI/SQLite 项目内实现。

主要文件：backend/knowledge.py、knowledge_text.py、knowledge_samples.py；模型入口在 model_adapter.py；前端独立在 frontend/src/features/knowledge/。原活动素材流程未与知识草稿强行混合，避免将医美内部答复误送入原保温杯模拟投放链路。

## 验证

自动测试使用临时数据库，不改现有商品/活动/订单。命令：

```powershell
.\.venv\Scripts\python.exe -m pytest backend -q --basetemp=tmp/pytest-rag-complete
npm.cmd --prefix frontend run build
node scripts/browser_knowledge.cjs
```

浏览器脚本只允许连接 localhost:8026 的隔离回放服务；先设置独立 DEMO_DATA_DIR 和 MODEL_PROVIDER=replay 再启动，不能对日常业务数据执行验收脚本。测试结果保存到 tmp/rag-acceptance/browser/result.json，截图在同目录。

- 新增 64 项后端检查：真实 FTS 中文匹配、两场景各 20 个示例检索问题、内容范围和渠道隔离、过期/待审核排除、日期错误提示、无依据/仅脚本阻断、版本更新、归档、引用快照、重复请求、生成中资料变化、模型失败与伪造引用、导入格式和 PDF、重启持久化。
- 两场景各 20 问属于自建功能回归集，只验证这些问题能找到相关类型资料；没有声称是独立行业评测、完整 Recall@K 或生产检索准确率。
- 浏览器检查 17 项：保留首页八入口、两场景完整回放链路、文件上传、审核、引用预览、编辑确认导出、刷新恢复、失败保留输入、390px 无溢出、减少动画、创意模块访问同一草稿。无浏览器脚本异常。
- motion_validate_file：5 个新增界面/样式文件均无 error/warning，98–100 分；若干 info 提示由复用的 Field 标签和外部 CSS 按压反馈实现，实际浏览器另行检查。
- 智谱真实验证：scripts/check_knowledge_live.py，仅发送内置虚构资料，使用现有免费型号 glm-4-flash-250414。医美返回 200、2 个引用、约 7.47 秒；直播返回 200、4 个引用、约 10.12 秒。结果仅保存在隔离测试目录，不自动确认或投放。
- 免费型号允许列表和官方接口限制继续沿用；真实调用成功不等于服务商以后不会改变价格/额度，免费定价核对记录沿用 2026-11-10 的接入文档。
- 已有 FastAPI/Starlette TestClient 的 httpx 弃用提示仍存在，不影响当前测试；本次没有为消除提示升级无关依赖。

最终回归结果：后端 163 passed、1 条上述弃用提示；TypeScript 检查和 Vite 构建通过。启动本地正式数据目录前已保存 SQLite 备份及旧记录摘要；启动后核对原有 72 条非知识库记录内容哈希一致，未覆盖原商品、活动、订单或执行记录。本机 8000 端口的工作台、官网、知识库空间及资料接口均返回 200。独立验收服务已停止，日常本机服务保持运行。页面截图：knowledge-workspace.png。
