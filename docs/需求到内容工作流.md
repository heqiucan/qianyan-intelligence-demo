# 需求素材到内容草稿：八项流程与操作

本次在既有八个主菜单中增加需求工作空间。数据保存在本机；处理对象是导入的关键词、评论或问题记录，不自动认定为真实客户、购买意向或机构事实。

## 从哪里进入

| 原有主菜单 | 新增页签 | 用途 |
| --- | --- | --- |
| 增长工作台 | 需求任务工作台 | 描述目标、选模板、预览后启动、查看任务 |
| 商品与品牌 | 需求素材与词库 | 导入表格、整理词库、查看原文来源 |
| 效果与获客 | 需求筛选与确认 | 过滤结果、人工确认、排除、分组、撤销 |
| 营销与创意 | 需求选题与 FAQ | 承接确认结果、检索事实、生成带引用草稿 |
| 异常与待办 | 需求任务待办 | 查看暂停、中断、失败、待补资料和待确认任务 |

默认经营首页、直播、电商和行业知识库仍在原位置。需求页按机构空间工作，不借用电商活动的商品事实。

## 推荐操作顺序

1. 在“需求素材与词库”选择机构空间，上传 CSV、TXT 或 XLSX。选择工作表、需求文本列和可选日期列，核对首行是否为表头。**每个选中的非空文本单元格成为一条记录**，不是把整行自动拼成一个客户。
2. 查看导入预览后确认。原文、文件名、工作表、物理行号、列号和日期保留；空白与全半角只影响另存的规范化文本。重复记录有标记，去重后的结果仍保留重复来源。
3. 需要重复使用关键词时，新建词库，分别填写主题词、意图词和排除词。每类最多 30 个词、每词最多 60 字；保存更新产生新版本，既有任务保留原快照。
4. 进入“需求任务工作台”。选择素材批次及四种内置模板之一：整理词库、分析需求、创建选题卡、内部 FAQ。也可把筛选配置另存为自定义模板。模板不携带素材批次或客户原文。
5. 用一句话描述目标，点击“根据目标生成可编辑配置”。真实模型只返回建议配置；回放模式只做规则辅助。检查所有条件后点击“预览筛选结果”。此时仍未启动任务。
6. 核对输入、匹配、排除、重复及上限截断数量，再点击“确认并启动任务”。修改配置会使旧预览失效，必须重算。
7. 在结果页查看原文、命中理由、时间、来源、分类和辅助提示。选择当前页或全部筛选结果后，确认处理数量，再批量确认、排除、修改分类或按主题分组。改变筛选条件会清空选择。撤销会保留操作历史，已被后续改动的记录会报告冲突。
8. 选择已确认记录，转为选题或 FAQ。相同确认版本默认复用同一份下游任务；明确勾选“重新创建一版”才增加新任务。下游选题仍需确认，再点击“生成有引用的依据草稿”。打开知识草稿，核对原文引用并人工确认。

## 已有知识库里的词表怎么用

如果此前把关键词表误存为“事实资料”，在知识库的“查看资料与审核 → 编辑为新版本”里改为“需求素材（关键词 / 问题）”，保存并重新核对。然后进入需求素材与词库，展开“已有知识库词表？复制到需求素材”，选中该资料并复制。

更改用途是明确的人工操作，系统不会自动迁移你的文件。原知识版本与旧草稿引用保留；重新分类后，旧草稿会提示原依据已变化。单纯复制为需求素材不会改变原知识资料用途。

## 筛选与处理的实际含义

- 主题词支持“任一”或“全部”；填写意图词后至少命中一个。排除词优先生效。
- 启用语义补充后，仅在“任一主题词”模式补充相近表达。时间、意图词及排除规则继续生效。未安装或无法运行本地模型时，明确显示关键词回退。
- 日期缺失可保留、标记待核对或排除；时间排序使用完整时间戳。数量上限是最终候选截断，不假装已处理超出部分。
- 分类、否定表达、同行/合作、经历分享均为确定规则提示，需要人工判断，不是购买概率或身份识别。
- 原文精确去重与主题分组分别处理。相近表达需要人工决定是否归组；系统不按昵称合并人员身份。
- 本轮未接平台抓取、自动私信、自动投放或真实线索系统。来源是本地导入或显式虚构样例。

## 任务状态与恢复

任务配置、素材、词库和模板版本在启动时保存为快照。单个本地工作线程逐条处理，每条结果及计数一起提交。暂停在当前处理单元边界生效；恢复仅处理尚未保存的条目。服务中断后，排队或处理中任务显示“中断待恢复”，由用户明确恢复。失败和取消都保留已保存的进度；取消不可恢复，可创建新任务。

资料不足的内容任务进入“待补资料”，并保留具体缺口。补充、审核事实后可重新生成；也可人工排除该需求。存在已确认而缺事实依据的记录时不能标记本轮完成。部分批量处理失败会逐条列出原因，不覆盖其他页面已修改的版本。

## 引用与事实边界

需求素材只提供问题方向。事实检索在排序前排除 `demand` 类型，并只使用同空间、同渠道、已审核且在有效期内的知识资料。需求内容生成进一步只选用 `facts` 原文句；规则和历史脚本不能替代事实。

当前内容生成方式是**原文依据组合**：真实模型从检索到的事实句中选编号，服务端保留原文并附引用；回放模式按已有片段摘录。此方式不会把需求中的“预算 3000 元”变成机构报价，资料未明确价格时返回缺口。医美个体判断和疗效问题留待专业处理，医美内容不转入商品成交活动。

每份草稿保存“原始需求 → 人工确认版本 → 下游任务”和“事实文档 → 版本 → 引用片段”两条来源链。上游撤回确认、修改分类或事实版本变化后，会提示过期并阻止继续确认旧草稿；重新生成保留旧草稿并保存新结果。引用存在不等于已经验证结论，仍需逐段人工核对。

## 工程实现与参考

- 沿用项目 FastAPI、React、SQLite，不引入远程任务平台。可恢复队列、预览签名、逐条检查点、版本校验、批量撤销和需求到事实的隔离按本项目实现。
- CSV 读取参考 [CPython 3.12 的标准库实现](https://github.com/python/cpython/blob/3.12/Lib/csv.py)（PSF 许可），保留物理位置并限制输入大小。
- XLSX 使用 [openpyxl 3.1.5 官方文档与上游](https://openpyxl.pages.heptapod.net/openpyxl/)（MIT/Expat；官方仓库位于 Heptapod），按其建议安装 [defusedxml 0.7.1](https://github.com/tiran/defusedxml)（PSF 许可）。本项目另行加入 5 MiB 上传、50 MiB 解压、2,000 行、20 列、12 万字符等边界与公式跳过、稀疏坐标检查。
- 页面参考本地固定提交的 Motion Site Builder `product-ui` 参数及后台参考，沿用项目字体与颜色。当前会话未加载 Motion MCP，实际运行同一上游本地检查器，不将静态得分当作业务验收。
