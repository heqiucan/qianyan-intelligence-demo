# 直播工作台第一阶段：抖音场景本地模拟

入口：增长工作台 → 直播工作台（第三个同级页签），路由 `#/overview?tab=live`。

## 使用

1. 选择所属营销活动；如需新商品，在商品资料或商品目录与 SKU 中保存。
2. 新建直播场次，填写负责人、时间，显式选择商品/SKU 加入货盘。
3. 核对货盘价格、来源、资料版本，确认货盘。
4. 在本场模拟控制台保存模拟账号名称、直播间名称。不需要平台密码。
5. 启动模拟，手动发送弹幕、进场、关注事件；测试暂停、恢复和停止。
6. 刷新或重新进入场次，检查配置、状态、事件和日志恢复。

## 边界

- 复用原直播场次与货盘，原营销入口继续可用。
- 每场独立保存模拟配置、控制状态及最近 200 条事件、200 条操作日志到 SQLite。
- 这里的运行状态仅代表手动模拟模式，刷新/重启不会启动后台任务。
- 商品资料版本变化时提示更新货盘，阻止继续启动或发送模拟事件；已有快照不会被覆盖。
- 使用修订号拒绝过期页面写入，使用请求标识避免同一请求重复执行。
- 尚未实现语音播报、音色、自动回复、抖音登录、真实弹幕、推流或真实公屏发送。在线人数显示未接入。
- 模拟账号是本场的测试名称配置，尚非跨场次的平台账号授权管理。

## 验证方式

后端：`python -m pytest backend -q --basetemp=tmp/pytest-local`。

前端：在 frontend 运行 `npm ci`、`npm run build`；在根目录运行 `.venv\Scripts\python.exe scripts/run_e2e.py`。

新增 `backend/test_live_workspace.py` 检查状态切换、幂等、并发版本冲突、资料更新、场次隔离；新增 `scripts/browser_live_workspace.cjs` 通过真实浏览器创建场次、确认货盘、配置并模拟互动、刷新恢复及检查 390px 和减少动画。

浏览器 runner 使用独立临时数据库和本机端口；测试服务通过标准输入请求正常退出，释放 Windows 数据库锁后清理。旧业务测试的固定截止日期已改为相对日期，避免随日期过期误报。

设计使用 Motion MCP 的 product-ui 参数与 CoastSignal 后台参考，沿用原黑紫界面和现有组件，不新增依赖。后端验收参考 FastAPI 官方 TestClient 流程；场次模拟状态、事件与版本保护为本项目实现。

参考：https://github.com/fastapi/fastapi/blob/master/docs/en/docs/tutorial/testing.md
