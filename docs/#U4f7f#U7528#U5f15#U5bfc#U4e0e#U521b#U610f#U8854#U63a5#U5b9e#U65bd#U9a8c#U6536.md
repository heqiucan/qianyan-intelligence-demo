# 使用引导与创意衔接 · 实施与验收

实施日期：2026-11-13。

本轮对应用户确认的“先让人会用，再把 Agent 内容接到活动创意”。保留黑紫色首页、紫色球体、四张指标卡、八个一级入口和独立官网。没有扩建医美 CRM、直播场次或真实投流接口。

原首页重复的五步进度被统一的六步活动路径替代；未删除功能入口。新组件独立放在 `frontend/src/features/journey/`。

## 推荐体验路线

1. 打开原桌面启动入口或 `http://127.0.0.1:8000/#/overview`。
2. 点击“从任务开始”，选“直播电商”，打开“跟着示例走一遍”。
3. 点击“从新建活动开始”，填写名称和活动策略，创建活动。
4. 在活动创意中点击“让 Agent 准备直播内容”，核对关联活动。
5. 使用“预置虚构示例”，点击“开始任务”；模型配置和调用边界沿用原实现。
6. 查看执行过程与引用，修改并保存需要调整的内容，人工确认，再标记任务完成。
7. 点击“转为活动创意”，核对目标商品；整理标题、正文、脚本，勾选说明后转入。
8. 新素材保持草稿状态；核对商品事实、确认素材，再创建并确认模拟计划。
9. 在运行计划中“体验购买”，完成模拟下单；“查看订单来源”返回现场互动记录。
10. 在同一统计范围复盘、保存报告。需要消耗、曝光样例时另载入模拟批次，不与现场订单混算。

独立 RAG 产物也可以在“营销与创意 → 行业知识草稿”中人工确认后转入，无须为此再创建 Agent。医美 FAQ 可以确认和导出，不能进入商品成交计划。

## 业务与数据约束

- 转入过程不调用模型、不建立投放计划、不自动确认素材、不发生支付。
- 目标商品由用户逐项核对，系统没有自动证明知识库中的商品就是目标商品。规则核对只覆盖已有实现支持的字段和部分表达。
- 原知识草稿正文、逐段引用、资料版本、待核实事项、来源模式和确认记录保存为 `knowledge_origin` 快照。转入窗口整理过的文案另存为创意字段。
- 后续人工修改或重新生成创意会保留来源链路，但不会自动为新文字重新分配逐句引用。页面明确提示这个限制。
- 同一知识草稿版本转入同一活动只建立一份素材。重复请求或再次点击会打开既有素材；修改请在创意编辑器另存版本。
- Agent 关联的活动在创建任务时保存。任务已绑定活动时，转入窗口和服务端均限制转入该活动。
- 每次新转入检查草稿版本、确认状态、引用可用性、目标商品版本和人工确认。
- 引用资料更新、归档或失效后，旧快照继续保留；再次确认素材、创建计划、启动或恢复计划会重新检查并拒绝使用失效依据。已经运行的计划不会被静默暂停。
- 历史任务、活动、报告和订单不会因本轮新增字段被重写。旧任务没有关联活动字段时，按独立任务处理。
- 资料来源可追溯不等于因果增量归因，也不代表广告审核通过。

## 实现位置

- `backend/creative_handoff.py`：知识草稿转入、同版本去重、引用状态和确认边界。
- `backend/agents/schemas.py`、`routes.py`：可选活动关联；医美任务拒绝关联商品成交活动。
- `backend/knowledge.py`：返回转入状态、原因、既有转入记录和绑定活动。
- `backend/main.py`：创意修订保留来源，在素材确认和投放入口重新校验引用。
- `frontend/src/features/journey/`：任务起点、路线说明、活动进度、数据来源帮助、转入窗口和创意来源。
- 原知识库和 Agent 编辑器复用同一个转入组件；通过地址中的页签、资料空间、草稿或任务 ID 定位对象。

继续使用现有 React / TypeScript、FastAPI / Python、SQLite 和智谱适配器，没有新增运行依赖或切换模型。
