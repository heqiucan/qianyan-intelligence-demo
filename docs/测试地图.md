# 测试地图

核对：2026-11-23。测试脚本按领域映射，测试数据库和日志必须隔离日常 `data/`。测试不是功能清单：某项通过只说明该脚本覆盖的行为。

## 分层规则

| 层 | 适合验证 | 入口 |
| --- | --- | --- |
| 纯逻辑/数据 | 路由转换、数据排名、买家构成、CSV、格式化 | `node --test scripts/test_workspace_navigation.cjs`；`node scripts/test_analytics_visuals.cjs` |
| 后端领域 | 状态机、版本、事务、幂等、权限边界和数据保存 | `backend/test_*.py`；按改动域选择，独立 `--basetemp` |
| 浏览器流程 | 页面层级、导航、窄屏、表单、媒体资源、打印和主题 | `scripts/run_e2e.py --scripts browser_*.cjs`，仅 `127.0.0.1` 随机隔离端口 |
| 构建/静态 | TypeScript、Vite、Motion、差异空白 | `npm.cmd --prefix frontend exec -- tsc --noEmit -p frontend/tsconfig.json`；`npm.cmd run build`；项目 lint |

### 测试前置条件

- 纯逻辑测试不启动服务，不访问网络。
- 后端 pytest 使用 `backend/conftest.py` 的离线语义默认；语义模型实测必须单独注明并使用独立资源。
- 浏览器测试由 `scripts/run_e2e.py` 启动随机端口和临时数据库，拒绝日常 8001；需要使用 `DEMO_FRONTEND_DIR` 指向被验收构建。
- 语音测试需要 Windows 中文系统音色；媒体测试需要 FFmpeg；摄像头测试使用 Chromium/Edge 测试设备，不自动打开用户实体摄像头。
- 测试日志、截图和 PDF 写入 `tmp/`。不把验收请求写入日常 `data/`，不读取用户业务库作为断言数据。

## 常用命令

从项目根目录运行。表中的 `test_*.py` 位于 backend，`browser_*.cjs` 和纯逻辑脚本位于 scripts，不能把表中的文件模式直接传给 PowerShell 外部命令。按实际文件名选择，或先用 `Get-ChildItem` 展开列表。

```powershell
# 前端类型与独立构建，避免覆盖正在分享的版本
npm.cmd --prefix frontend exec -- tsc --noEmit -p frontend/tsconfig.json
Push-Location frontend
try { npm.cmd exec -- vite build --outDir ../tmp/docs-check-dist } finally { Pop-Location }

# 纯逻辑
node --test scripts/test_workspace_navigation.cjs
node scripts/test_analytics_visuals.cjs

# 存储专项与后端完整回归
$testRun = [guid]::NewGuid().ToString('N')
.venv\Scripts\python.exe -m pytest backend/test_storage_core.py -q --basetemp="tmp/pytest-storage-$testRun"
# 仅共享逻辑变化或发布整合需要时扩大
.venv\Scripts\python.exe -m pytest -q --basetemp="tmp/pytest-full-$testRun"

# 指定浏览器脚本；不使用通配符，避免 PowerShell/Node 参数歧义
$previousFrontend = $env:DEMO_FRONTEND_DIR
try {
  $env:DEMO_FRONTEND_DIR = Join-Path (Get-Location) 'tmp/docs-check-dist'
  .venv\Scripts\python.exe scripts/run_e2e.py --scripts browser_workspace_v4.cjs browser_agent_workspace.cjs browser_feedback_workspace.cjs --timeout 300
} finally { $env:DEMO_FRONTEND_DIR = $previousFrontend }
```

`run_e2e.py` 的 `--scripts` 参数只接受 `browser_*.cjs` 文件名。一次只跑某个脚本时也必须使用隔离服务；不要直接在用户打开的 8001 服务上执行会写入数据的浏览器脚本。

## 历史脚本与执行限制

- `scripts/check_deepseek_live.py --run` 是显式真实业务验收：仅在当前授权下执行，用隔离虚构资料测试创意与Agent，最多8次请求；可能产生账户费用。默认无参数不调用，不进入pytest或常规replay流水线。

- `scripts/browser_navigation.cjs` 仍断言“增长工作台”等旧名称；`scripts/browser_live_workspace.cjs`、`scripts/browser_knowledge.cjs` 也存在旧界面定位。它们是历史覆盖资产，不是当前保证通过的入口。
- `scripts/run_e2e.py` 的默认列表仍包含这些脚本，因此当前应显式传 `--scripts`。本轮仅修文档，没有擅自改运行器或降低旧断言。
- 需求/知识浏览器脚本未在本轮重新适配全部新层级，运行前先检查定位、数据前置和输出目录；不能把旧通过记录当作本次通过。
- 运行器会写固定验收日志目录，多个运行器并行可能覆盖日志；默认串行组织一个隔离服务内的多个脚本。
- 脚本有初始数据依赖时按脚本前置建样例；不能为让测试过关而读真实业务库。真实模型验证与普通离线回归分开。
- 本轮只做文档路径/API/状态与命令参数的静态核对，未执行本表业务回归；完整通过数仍查看对应日期的历史验收记录。
- 模型配置专项：`backend/test_configure_deepseek.py` 使用假密钥验证保密和配置保留。`scripts/browser_model_provider.cjs` 是明确的只读例外，可检查日常8001的模型设置，拦截所有业务写请求，不点击连接测试；不能据此放宽其他浏览器脚本的数据隔离要求。DeepSeek真实连接验收见 `docs/DeepSeek接入说明.md`。

## 完成判定

- 编译通过不等于页面完成；涉及页面必须实际检查桌面、窄屏、键盘/焦点、减少动画和错误/空状态。
- 健康接口通过不等于业务完成；必须完成对应动作链和保存结果核对。
- 静态 Motion 检查不替代浏览器行为；手动视频预览不因 lint 提示改成自动播放。
- 失败、超时、重复提交、刷新、后退和离开保护必须验证输入、快照、运行状态和资源是否正确保留或释放。
- 未捕获异常和非预期API失败应为0；故障注入的预期失败单独断言。跳过项记录原因，不计为通过。
