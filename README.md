## 启动

这份工作区已经准备好依赖和前端构建时，可双击根目录 **`start-demo.cmd`**（或桌面的“启动浙衍 AI Demo”快捷方式）。启动器会等待服务就绪后自动打开 **http://127.0.0.1:8000**；如果 Demo 已在运行，则直接打开现有页面。保持首次启动的命令窗口打开，按 Ctrl+C 停止服务，业务数据保留。启动失败时窗口会保留错误信息。

也可以在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/start_demo.py
```

启动器只检查和启动，不静默下载依赖。检查准备情况、不启动服务：

```powershell
.\.venv\Scripts\python.exe scripts/start_demo.py --check
```

首次复制到另一台电脑，先安装 Node.js 24 和 Python 3.12/3.13。Windows PowerShell 中依次运行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Set-Location frontend
npm.cmd ci
npm.cmd run build
Set-Location ..
.\.venv\Scripts\python.exe scripts/start_demo.py
```

端口被其他程序占用时使用 `--port 8001`；如果检测到本 Demo 已运行，启动器直接复用。修改后端后需先停止旧服务再启动，修改前端后运行 `scripts/start_demo.py --build`，它只使用已经安装的前端依赖重新构建。Python 当前实测环境为 3.12.14，依赖已固定在 `backend/requirements.txt` 和 `frontend/package-lock.json`。

## 演示路线

1. **增长工作台**：保留紫色球体首页、四张指标卡、活动策略、下一步入口和活动进度。创建活动并填写目标、受众、卖点和周期。
2. **商品与品牌**：编辑商品事实、资料来源和图片；保存前核对差异，原活动继续保留原资料快照。
3. **营销与创意**：按当前模型模式生成两组草稿，编辑、对比、导出海报。新增“载入核对示例 → 核对当前文案 → 查看依据和修订建议 → 保存新版本 → 人工确认”流程。
4. **广告投放**：用确认的素材创建计划，核对预算和周期后模拟启动；支持暂停、恢复、结束和调整草稿。
5. **消费者演示**：从投放计划进入广告预览、商品页、订单确认和模拟付款，没有真实扣款。
6. **效果与获客**：按同一活动、来源、计划、日期查看支付、订单、新客、客单价和投放指标，追溯订单及消耗依据。
7. **异常与待办**：检查预设异常规则，查看依据并记录处理过程。
8. **AI 优化复盘**：形成复盘和调整草稿，人工确认后观察；无数据时不编造改善结果。
9. **活动报告**：保存选定范围的报告快照，支持打印和另存 PDF。

八个功能入口均在主导航，消费者演示从投放计划进入。示例检查不会保存素材；采用建议只修改编辑输入，保存才建立新版本。AI 生成按每条记录标注模型或回放来源，事实核对为实际规则执行。

首次启动内置两份已确认素材和两个运行中的模拟计划，可直接从第 5 步演示；也可以新建活动，从头走完整流程。

## 数据和模拟边界

| 项目 | 当前行为 |
|---|---|
| 商品、活动、版本、确认、计划、订单和日志 | 通过后端保存到 SQLite，刷新和重启后仍保留 |
| AI 文案、脚本与复盘 | 根据商品资料与已计算指标生成回放或智谱免费模型内容；逐条记录来源 |
| 图片、已有视频 | 本地上传，支持 PNG/JPEG/WebP 和 MP4/WebM，单文件最多 20 MB |
| 海报 | 浏览器真实渲染并导出 PNG，图片与文案使用当前素材快照 |
| 广告平台、预算消耗、付款 | 模拟；不连接真实广告账户，不扣款，不自动花费 |
| 固定历史 D0 | 固定虚构数据，属于初始演示活动；新活动没有这份历史 |
| 现场互动记录 | 真实记录本系统内的测试点击、商品页浏览与模拟订单，包含此前保存记录，可按 UTC 日期筛选，不与 D0 混算 |
| 独立模拟批次 | 运营预览确认后载入固定场景，单独保存订单、消耗、计划配置快照；不写入现场订单，也不随机刷新 |
| ROI 与获客成本 | 本次互动没有对应广告消耗，显示不可计算；支付 ROI 不等于利润 |
| 新老客 | 基于虚构测试买家历史；重复购买后计作老客，未知历史保留未知 |
| 内容校验 | 实际执行部分数字价格、容量、时长与保证性表述核对，逐条显示依据；促销、引用等需人工核查，不保证完整合规或过审 |

预算和日期是演示计划参数，模拟运行由人工按钮控制；启动/恢复需处于计划周期，目前没有定时投放调度器，也不会按预算自动消费。活动预算上限为规划参考，尚无跨计划自动分配或预算扣减。

当前仍是单店，已支持直播商品目录、多 SKU、场次及货盘。原普通活动的默认商品流程继续保留。人工录入库存仅供参考，不自动扣减；优惠说明不改变模拟订单结算价。退款、成本利润、平台实时直播、完整销售 CRM 与代运营合同回款尚未接入。受众/卖点文字保存为策略与快照，回放模式使用有限文案结构，不声称理解任意营销指令。观察比较要求同源与对应计划、配置版本；现场基线须具备完整单计划日期窗口，等长观察时间未到时继续等待。

默认数据位于 `data/demo.sqlite3`，上传文件位于 `data/uploads/`。停止服务后可备份整个 `data/` 目录。不要删除已有数据来“刷新页面”。需要独立的新演示空间时，可在 `.env` 中指定另一空目录，例如 `DEMO_DATA_DIR=data-demo2`；系统只会在新目录初始化，不清理原数据。

## 配置模型与访问码

将 `.env.example` 复制为 `.env`，通过 `scripts/start_demo.py` 启动时读取。进程中已设置的环境变量优先。直接运行 uvicorn 或 Docker 时请通过宿主环境或 `--env-file` 提供变量；后端不会自行加载 `.env` 文件。

## 局域网与公网

只需要同一 Wi-Fi 下同事访问时，可运行：

```powershell
.\.venv\Scripts\python.exe scripts/start_demo.py --host 0.0.0.0
```

其他设备使用 `http://本机局域网IP:8000`；需要网络互通且 Windows 防火墙允许相应端口。`127.0.0.1` 只代表访问者自己的电脑，不能作为给同事的公网地址。

项目提供 Docker 部署文件，单个服务同时提供网页与 API：

```text
docker build -t zheyan-demo .
docker run --rm -p 8000:8000 --env-file .env -v zheyan-demo-data:/data -e DEMO_DATA_DIR=/data zheyan-demo
```

公网部署需要可运行 Docker 的服务器或容器平台，并配置 HTTPS、访问码和挂载到 `/data` 的持久卷。没有持久卷的平台在重启或重新部署后可能丢失订单与上传文件。当前结构适合单实例共享演示；不要直接作为多租户生产系统使用。

**2026-11-11 已创建并通过公网地址验证临时分享链接。** 使用 Cloudflare Quick Tunnel，网址随分享进程有效，关闭电脑、停止服务后失效，重新创建会换地址；不是独立服务器上的长期托管。分享工作台使用 `tmp/share-runtime/demo-data` 独立示例数据、随机访问码和 `replay` 模式，不加载本机 `.env` 或智谱密钥。官网可直接浏览，工作台需输入访问码。会话地址和访问码保存在忽略提交的 `tmp/share-runtime/session.json`；双击 `stop-share.cmd` 停止本次分享。

详见 [临时公网分享说明](docs/临时公网分享说明.md)。Docker 文件已提供，但本机 Docker 构建与云端启动尚未验证；选定长期部署平台后应复核页面、静态资源、API、持久化和访问码，而不仅是健康接口。
