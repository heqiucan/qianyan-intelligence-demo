## 4. 推荐完整体验路线

### 直播营销主线

1. 在工作台选择或创建营销活动。
2. 进入“商品与品牌 → 商品目录与 SKU”，录入商品、规格、价格和来源。库存只是带来源的人工参考值。
3. 进入“营销与创意 → 直播场次与货盘”，建立场次、填写负责人 / 时间、选择商品 SKU、排序并保存。
4. 人工核对货盘价格、优惠说明与事实资料，确认货盘版本。
5. 从货盘条目点击“让 Agent 准备本商品讲解”；也可以直接生成活动文案。前者适合展示检索、引用和人工审阅过程。
6. 查看 Agent 执行记录和草稿引用，修改后保存、人工确认、完成任务。
7. 将草稿转为活动创意。核对目标商品和 SKU，产物仍是待确认素材。
8. 核对创意并人工确认，再到“广告投放”创建计划、人工启动模拟投放。
9. 从计划进入广告 / 商品页，完成模拟购买，付款不扣款。
10. 到“效果与获客 → 直播场次复盘”查看本场订单、SKU 和成交来源，保存复盘 / 报告。

场次、货盘版本、条目、商品、SKU 快照贯穿内容、计划、订单和报告。后续商品或货盘改价不会回写旧订单；旧版本内容不能绕过检查重新确认 / 启动。

### 原商品活动链路

原流程继续可用：商品资料 → 活动策略 → 创意生成与事实核对 → 人工确认 → 模拟计划 → 模拟购买 → 同源分析 → 复盘 / 优化草稿 → 活动报告。普通活动保留其商品快照，不能把直播 SKU 价格误套成原演示商品的 99 元。

### 医美内容链路

机构知识库 → 导入并人工审核资料 → 关键词检索 → 生成内部 FAQ / 咨询预约说明 → 查看引用、修订、人工确认、导出。当前没有医美咨询线索、预约、到店 CRM；医美 FAQ 不能转入商品成交计划。

## 5. RAG 和 Agent 到底已经做了什么

### RAG：给生成提供可查看的依据

- 入口：“商品与品牌 → 知识库与 RAG”。按医美 / 直播及机构 / 品牌资料空间分类。
- 支持 TXT、Markdown、文本型 PDF 和粘贴文本。核对解析、适用范围、有效期，人工标为可用后参与生成。
- 技术是 **jieba 中文分词 + SQLite FTS5/BM25 关键词检索**。展示命中词、原文段落、资料版本、PDF 页码等引用信息。
- 历史脚本不能单独当作商品或机构事实。资料文字和用户补充要求不能自行改变工具权限或代替事实审核。
- 草稿位于“营销与创意 → 行业知识草稿”，支持修订、人工确认、Markdown 导出。
- 直播知识草稿可以经确认后转入活动；Agent 产物还要求任务完成覆盖当前草稿版本。
- 已失效资料会触发重新核对；历史草稿 / 引用快照仍保留。
- 未实现向量数据库、混合检索、扫描 PDF OCR。不要把“有引用”描述为完整真实性或合规保证。

### Agent：把有限步骤组织成可追踪的任务

- 入口：工作台“交给 AI 处理”，或从直播货盘的指定 SKU 启动。
- 流程：选择关键词检索 → 读取依据 → 判断资料缺口 → 生成 / 编排 → 检查 / 有限修订 → 保存待审阅草稿 → 人工确认并完成。
- 自定义 Python 有界任务执行器，模型返回结构化动作，由服务端校验并调用白名单工具。没有引入 LangGraph / LangChain，也不要声称已实现模型原生 `tool_calls`。
- 任务持久化，记录实际工具事件；支持继续、重试、取消。服务中断后需手动继续，不自动重复执行。
- 已完成任务的草稿修改后，可以“重新打开审核”再确认；保留 `completion_history`，重新打开本身不调用模型。
- 医美是带引用的内容生成；直播模式由模型选取事实原文，再结合中性衔接编排，页面明确显示来源。回放模式按规则和摘录执行，不伪装成真实模型推理。
- 每轮最多 7 次模型调用、12 步、2 次搜索，最多 5 轮；240 秒预算在步骤边界检查，不等于强制中断外部请求。
- 不自动发布、不操作真实广告账户、不付款；同一数据库按单实例运行。

### 草稿转入创意的边界

`knowledge_origin` 保存原稿、引用、版本、确认与来源快照；同一草稿版本转入同一活动去重。活动 / 场次绑定不能随意换目标。转入不自动确认素材或启动计划。人工改写创意后仍保留来源链，但不会自动为每个新句子重新分配引用。

### 分享脚本已知待改善点（没有在本次修复）

1. 没有单实例保护；重复启动会覆盖状态 / 日志并共用演示库。
2. `status` 只读文件，不检查进程 / 公网；掉线后可能仍显示 `running`。
3. 连接阶段没有明确总超时，不能只因出现网址就宣布可访问。
4. `Ctrl+C` 通常清理子进程，但可能留下 `running` 与 `stopped_at` 并存的记录；正常使用 `stop`。
5. `stop` 等待约 10 秒后会输出当前状态，不保证已经成功停止；异常时先排查，不能盲目重开或杀旧 PID。
6. `分享信息.txt` 是额外保存的文件，可能旧于会话记录。

临时分享不是长期托管。GitHub 上有源码也不等于网站已经部署。若用户只要链接，先尽快给出已生成的网址并准确说明验证状态，再完成验证，不让用户反复催要。
