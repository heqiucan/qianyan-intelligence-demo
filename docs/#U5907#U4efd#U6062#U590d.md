# Demo 本地备份与恢复

备份命令使用 SQLite `Connection.backup()` 创建一致的数据库快照，可以在本机 Demo 运行时执行。它随后复制 `uploads`，对每个上传文件核对复制前后内容，最后执行 SQLite 完整性检查及 SHA-256 校验。备份文件记录格式版本、应用版本、数据库迁移版本、文件大小及哈希。

在项目根目录的 PowerShell 中执行：

```powershell
.\.venv\Scripts\python.exe scripts/backup_demo.py backup --source data --output tmp/backups
```

命令会输出新的 `demo-backup-时间-随机编号` 目录。每次备份独立保存，不覆盖上次备份。默认只包括 `demo.sqlite3` 和 `uploads`；不会复制 `.env`、运行锁、模型配置或凭据。若上传目录混入环境文件、凭据或私钥，备份会拒绝完成，避免静默遗漏。上传文件是原始素材，仍应由资料所有者妥善保管。

把命令输出的目录路径代入以下命令，即可再次校验：

```powershell
.\.venv\Scripts\python.exe scripts/backup_demo.py verify tmp/backups/demo-backup-实际目录名
```

恢复必须指定**不存在的新目录**，父目录需要已经存在。它不会覆盖当前 `data`，也不会启动服务：

```powershell
.\.venv\Scripts\python.exe scripts/backup_demo.py restore tmp/backups/demo-backup-实际目录名 --destination tmp/recovered-demo
```

恢复会先检查清单、路径、哈希与数据库完整性，复制后再检查一次。已有目录、路径越界、符号链接、额外未列入清单的文件或内容被修改都会被拒绝。恢复成功后可以先检查资料数量与内容，再显式通过 `DEMO_DATA_DIR` 选择这个新目录启动；原始数据保留原样。

失败备份保存在 `.partial-*` 目录，不能作为正式备份使用；恢复中途失败的新目录带有 `.restore-incomplete` 标记，不能启动它。脚本不会递归删除这些目录。哈希用于发现损坏和篡改差异，不是备份发布者身份的数字签名。

数据库快照在备份时点保持一致。上传文件使用前后哈希核对；持续改写上传文件可能导致备份失败，应等待上传结束后重试。该工具只做本地备份，没有上传云端、加密存储或定时任务。测试使用独立临时数据，不访问日常数据库：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/test_backup_demo.py -q --basetemp=tmp/pytest-backup
```
