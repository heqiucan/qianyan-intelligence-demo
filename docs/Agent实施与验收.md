# 营销任务 Agent · 首个里程碑

实施日期：2026-11-12。

这一版给现有工作台加入一个受限的内容任务 Agent。它接收目标，选择检索关键词、读取依据、判断是否需要补充资料，再产出带引用的内容，经过检查后保存为待人工确认草稿。

原官网、紫色球体首页和八个一级功能入口保留。入口在 **增长工作台 → 交给 AI 处理**；页面下方是任务面板。Agent 的机构 / 品牌资料范围独立于工作台上方的活动统计筛选。

## 现在可以做什么

| 功能 | 实际行为 |
|---|---|
| 医美预约 FAQ | 依据资料生成内部预约问答，展示原文引用；不作诊断、项目适用性判断或疗效承诺 |
| 直播讲解稿 | 智谱选择事实句并安排顺序，后端将原文与固定的中性衔接语组合为开场、规格展示、收尾三段；标明“智谱选取依据 · 原文组合” |
| 资料检索 | 复用本地中文分词和 SQLite FTS5/BM25，只检索当前资料空间、渠道中已审核且有效的资料 |
| 执行记录 | 展示实际检索词、命中片段、读取原文、生成、复核、保存、请求补充或失败事件；没有编造进度百分比或模型思维链 |
| 补充并继续 | 没有事实依据时请求补充；要求可以直接填写，业务事实需导入知识库审核后再使用 |
| 生成后检查 | 校验引用结构、资料版本、有限保证性及性能表达；模型模式额外逐段复核；有问题最多修订一次，再失败则停止等待处理 |
| 人工审阅 | 查看引用快照、编辑正文、保存修订版本、确认、导出 Markdown，再标记任务完成 |
| 历史和恢复 | 任务与事件保存到 SQLite；刷新可恢复；服务重启后将进行中的任务标为中断，手动继续，不静默重发请求 |
| 取消与限额 | 限制动作名称、参数、调用次数、步骤数和资料范围；取消后不继续保存迟到的模型结果 |

医美内容目前是内部沟通稿。直播稿目前是依据编排稿，表达自由度有限；约一分钟是写作目标，未测量朗读时长。两者都不等于可直接发布的广告。

## 无真实资料时如何演示

1. 打开工作台，点击“交给 AI 处理”。
2. 点击“新建 Agent 任务”，选择医美获客或直播电商。
3. 保留预置任务，资料选择“预置虚构示例”。
4. 开始任务，查看“它做了什么”和“用到了哪些依据”。
5. 生成完成后逐段查看正文，点击引用打开原文。
6. 如需修改，可以编辑并保存修订版本，或填写补充要求让 Agent 再处理一轮。
7. 勾选人工核对说明并“人工确认并保存”，随后“标记任务完成”；草稿也可以导出。

虚构示例在首次创建该场景任务时写入独立的 `agent-demo-medical` 或 `agent-demo-live` 空间，不覆盖原机构资料、商品、活动或订单。示例审核人标记为“系统预置虚构示例（非真实业务审核）”。这与用户真实资料必须自行审核的流程不同。

后续提供资料时：进入“商品与品牌 → 知识库与 RAG”，建立对应机构或品牌空间，导入并核对事实资料、审核要求、历史脚本，标记可用；新建 Agent 任务时改选“我的知识库”。两个场景不会自动合并。历史脚本可以提供表达结构，但不能单独作为事实依据。

## Agent 的实现方式

本轮没有安装新的 Agent 框架。沿用已有 React、FastAPI、SQLite、智谱接口和 RAG 实现，增加下面这些文件：

- `backend/agents/schemas.py`：任务、动作和复核结果的结构及限制。
- `backend/agents/policy.py`：当前可选动作、已读 / 未读资料、检索历史；模型选择下一步，回放模式使用明确标注的规则。
- `backend/agents/tools.py`：受限检索、原文读取、生成 / 依据编排、检查、保存。
- `backend/agents/runner.py`：后台单工作线程、步骤检查点、模型互斥、错误恢复、取消后的结果丢弃。
- `backend/agents/routes.py`：创建、查询、继续、取消和完成任务的 API。
- `frontend/src/features/agent/`：任务输入、历史、执行记录、引用与补充要求；复用现有知识草稿编辑器。

模型通过现有 JSON 接口返回结构化动作，后端校验动作及参数后执行工具。**这不是智谱原生 `tool_calls` 协议的接入，也不是已安装 LangGraph。** 模型不能指定任意数据库查询、外部网址或命令，不能批准资料、切换机构范围或自行确认草稿。

执行链路为：

```text
接收目标
  → 模型选择关键词
  → 服务端在指定资料范围检索
  → 模型选择要读取的片段
  → 服务端核对原文与版本
  → 判断：继续检索 / 请求补充 / 产出内容
  → 引用与表达检查 + 模型依据复核
  → 必要时修订一次
  → 保存待审阅草稿
  → 人工核对与确认
  → 标记任务完成
```

检查、保存、人工确认的边界由后端控制，模型不能自行跳过。生成前、检查后和保存时会再次核对引用版本。已完成任务记录的是当时确认的草稿版本；之后正文或来源变化，任务页提示原确认结果不能沿用。

### 为什么直播稿采用依据编排

实际免费模型测试中，自由改写曾把“杯盖结构”扩写成“防漏”，把“容量标识”扩写成“查看剩余水量”。同一模型再次核对也出现漏判。因此，直播分支改成模型选择事实片段编号，后端只使用这些片段的原句，再加固定的中性衔接语；不存在的编号会被拒绝。

这能校验商品事实句确实来自原文，**不能证明原文事实真实**，也不能自动发现所有组合后的语义问题。页面如实显示生成方式，人工修改后的文字另标“含人工修订”。没有把自由改写失败后的摘录伪装成成功的自由创作。

医美 FAQ 保持有引用的生成式问答，仍可能有误读或遗漏，需要人工核对。表达规则仅覆盖列明的部分风险，不能宣传“完整合规审核”“保证过审”或“零幻觉”。

## 执行与费用边界

- 沿用已配置的 `glm-4-flash-250414` 免费模式与型号白名单，没有新增付费模型、自动型号切换或计费服务；本轮再次核对[官方免费模型说明](https://docs.bigmodel.cn/cn/guide/models/free/glm-4-flash-250414)。
- 每轮最多 7 次模型调用、12 个处理步骤、2 次检索；每个任务最多 5 轮。创建队列最多容纳 4 个待处理 / 运行任务，单工作线程顺序处理。
- 在步骤边界检查 240 秒运行预算；已经发出的模型请求仍按适配器的请求超时结束。这不是可即时中断远端推理的硬性总时长保证。
- 取消只停止后续工作并丢弃迟到结果；已经发往供应商的请求不能撤回。已存在的草稿保留。
- 其他 AI 操作占用模型时，本任务保留进度并提示稍后继续。限流、格式不符、网络错误不会自动回退成模型成功，也不会自动切换付费型号。
- 模型模式会把任务文字、检索到的相关片段发送到智谱。密钥只在服务端；回放模式不调用模型，正文明确标注为资料摘录。
- 本轮是单实例、本地共享演示实现；没有分布式任务队列、多租户权限或跨进程任务锁，不应启多个服务进程共享同一业务数据库。

## 验收记录

### 自动化与页面

- 185 项后端测试通过，其中 22 项为本轮 Agent 行为测试。覆盖两场景、真实 FTS 检索、资料未审核 / 范围错误、重复动作、失败恢复、取消后的迟到结果、来源中途变化、检查后修订、无效事实编号、人工确认、队列上限、访问码与重启恢复。
- 前端 TypeScript 检查和 Vite 生产构建通过。
- 浏览器完成 19 项交互检查：保留原首页 / 八个入口 / 官网，任务创建、过程记录、引用查看、修订、确认、完成、刷新恢复、导出、提交失败保留输入、补充后继续、取消，以及 390px 窄屏和减少动画设置。没有捕获到脚本异常。
- 按 `product-ui` 调用了 Motion MCP 获取参数和参考、阅读完整参考后实现，并做文件检查。相关 TSX 文件 99 分，仅提示按压反馈写在独立 CSS；新 CSS 100 分。实际页面另经浏览器与截图核对，静态分数没有替代业务验收。
- 自动化存在 1 条已有 Starlette / httpx 测试客户端弃用提示；当前测试通过，没有为本轮功能调整依赖版本。

### 真实免费模型

最后一轮测试使用独立临时数据库和虚构示例，两项任务均到达待审阅状态：

| 任务 | 模型调用数 | 单次观察耗时 | 实际产物 |
|---|---:|---:|---|
| 医美预约 FAQ | 5 | 16.23 秒 | 预约流程、接待时间、预约与评估区别；逐段引用 |
| 直播讲解稿 | 5 | 9.64 秒 | 原文事实选择与三段组合稿；保留事实片段和来源 |

这是两次功能验证的观测值，不是性能承诺或准确率评估。此前测试出现过格式错误、重复读取与事实扩写，因此保留手动继续和人工审阅。当前产品没有自动重试；验收脚本最多显式调用一次继续接口测试恢复，最终这一轮两项任务都未用到继续。

证据保存在忽略提交的 `tmp/agent-acceptance/live-result.json`、`tmp/agent-acceptance/browser/result.json` 和截图目录。测试使用隔离数据库，没有导入用户业务资料。

### 原数据与启动

更新前使用 SQLite 备份保存原数据库，并记录每条业务记录的哈希。新版启动后确认原有 **74 条记录逐条一致**，没有新增业务记录。官网、工作台、状态接口、知识库接口和新任务接口均正常响应。备份和核对结果位于忽略提交的 `tmp/agent-implementation/`。

最终本机服务也通过“测试免费模型连接”接口完成实际联网检查，返回 `live_verified: true`。初次在受限执行环境中启动时无法联网，已停止该实例并重新启动可联网的本地服务；没有让用户继续使用连接失败的旧进程。

本机地址仍为 `http://127.0.0.1:8000/`。桌面原启动方式与项目根目录 `start-demo.cmd` 继续使用。完成前端构建不代表旧后端已更新；后续改代码需要重启旧服务。本轮不重新建立或发布公网分享链接。
