## 产品定位

- 产品是营销获客与广告投流工作台，核心对象是营销活动、商品资料、创意、投放计划、模拟订单、效果复盘、Agent 任务和直播场次。
- 产品目标是可持续使用的营销运营工作台，Agent 是重要特点；当前本机部署与模拟平台是实现现状，不应把“永远只做 Demo”写成产品目标。已确认体验原则与当前能力分别见 [产品范围](product/产品目标与功能范围.md)。
- 真实平台接入、真实支付、真实抖音弹幕/礼物/人数/GMV、公屏发送、正式推流、真实商品卡和完整自动客服均需另行接入和验收。

## 页面与导航

- 一级入口为：工作总览、Agent 任务、商品与知识、营销与创意、直播工作台、广告投放、效果与复盘、待办与审核。
- Agent 任务是独立一级工作区；业务页面保留就地发起 Agent 的入口并传递商品、活动或场次上下文。
- 需求任务归属 Agent 任务，不再让需求步骤在多个一级页面之间来回跳转。
- 效果分析、优化复盘、活动报告、场次复盘和场次报告统一归入效果与复盘。
- 旧链接需要通过 `frontend/src/navigation.ts` 兼容；修改路由时必须保留已有参数和必要的返回路径。
- 桌面导航固定，窄屏使用菜单；页面内部可以有二级标签和详情路径。

## 数据与业务边界

- 商品、活动、创意、计划和直播货盘使用版本或快照语义；后续修改不能悄悄改写历史报告、订单或运行队列引用的旧快照。
- D0、模拟批次、现场互动记录分开统计；缺失值和真实的 0 分开显示。
- 没有逐日或逐时数据时不绘制假趋势；没有广告消耗时不计算 ROI、CPA 或 CAC。
- Agent 的执行进度来自后端保存的事件和状态，不用步骤配额编造百分比。
- 模型回放、系统语音、本地视频、浏览器互动和模拟投放必须明确标注实际边界。
- 商品事实、知识资料、需求素材和 Agent 引用范围要分开；需求记录不能直接替代已审核的事实资料。
- Obsidian 是用户指定的知识库编辑界面；项目读取 Markdown 资料，确认导入后才进入 SQLite 和检索运行。私人 Obsidian 库不能默认导入。

## 工程约束

- 2026-11-24 用户再次明确要求产品真实调用模型：日常工作台的AI生成/改写/复盘/Agent模型步骤使用已配置DeepSeek。配置或调用失败必须报告失败，不得静默回退模板，也不能以连接测试替代真实业务验收。replay仅用于明确标注的离线测试/样例环境，历史回放产物仍保留原来源，不改标成AI生成。确定性指标、审核规则、本地语音和媒体操作不需要为“真实AI”额外调用模型。

- 2026-11-24 用户明确指定后续项目模型调用使用 DeepSeek V4.1-Flash-1017；官方 API 标识为 `deepseek-flash`，当前映射由官方文档核对，别名未来可能升级，不宣称固定版本锁定。使用官方 `https://api.deepseek.com`，不自动回退其他提供者。密钥只在本机被忽略的 `.env`，普通测试继续 replay/mock；此次授权不扩大为无限自动调用或充值。DeepSeek按账户规则计费，不能延用智谱“免费”文案。

- 继续使用 React、TypeScript、Vite、FastAPI、SQLite 和现有依赖；没有明确理由不换框架、不加大型依赖、不拆微服务。
- SQLite 基础连接、事务和记录读写由 `backend/core/storage.py` 负责；业务初始化、迁移和种子数据由应用层负责。
- API 请求必须保留现有错误语义、请求标识、幂等和版本校验；不因页面重构新增重复提交路径。
- 页面主题支持浅色、深色和跟随系统；主题切换不刷新页面、不丢未保存输入、不停止正在运行的合法本地操作。
- 报告打印是独立白底输出；屏幕主题不能污染打印布局。
- 直播本地文件、摄像头、录音、Audio 对象和对象地址必须在停止、切换场次、离开和刷新时按现有规则释放。

## 协作与交付

- 开发前先读 `docs/INDEX.md`，再按功能责任矩阵读取当前模块和直接影响模块。
- 不全量读取无关文件；但共享入口、路由、数据存储、公共 CSS、模型适配器和跨模块交接修改时，必须扩大阅读。
- 修改共享能力后同时检查直接调用方和对应浏览器验收。
- 详细测试日志写 `tmp/`；对话只汇报通过数、失败原因和边界。
- 提交与推送授权遵循根目录 `AGENTS.md`：用户说“提交”默认包含推送当前跟踪分支；普通开发完成仍不自动上传。发布、购买服务、付费模型和平台申请需另行授权。
- 不删除或覆盖其他任务的未提交修改，尤其是 Codex 看板、文档、输出和启动文件。
