# 商品资料与活动版本衔接

2026-11-17 修复：最新商品已保存，但创意页仍使用旧活动的商品。

活动创建时会固定一份商品资料。修改“商品与品牌”不会追溯改写已有活动、素材和计划。此前创意页只用一行“活动默认商品”说明，用户容易误以为生成使用最新商品。

现在的操作：

1. 在创意页查看“本活动生成商品”和“最新保存商品”的名称、版本及售价。
2. 不一致时点击“使用最新商品创建活动”，核对新活动的商品、受众与卖点。
3. 点击“创建活动并使用此商品”；页面自动切换到新活动。
4. 点击“生成两组创意”。新素材、商品图、价格与规格引用新活动中的最新资料。

存在差异时直接点击“生成两组创意”，会先询问使用哪一个商品，不会立即生成旧商品。明确选择“继续使用活动原商品生成”仍可为旧活动创作；历史素材的单组重新生成继续保留原素材商品版本。

新建表单固定展示打开时的商品版本。提交时后端在同一事务核对 `expected_product_version`；商品已更新则返回 409 且不创建活动。界面可“重新读取最新商品，保留表单输入”，核对后再提交。成功请求重复提交复用原活动，不因后续商品更新重复创建。

验证：后端版本保护、旧快照、生成输入、幂等及业务/主张相关回归 136 项通过；前端构建通过。既有浏览器 59 项通过；最终新增商品版本专项 10 项通过、0 个浏览器运行时错误（分开执行）。浏览器在随机端口、临时 replay 数据库核对新旧商品流程及 390px 窄屏、减少动画，不把虚构测试数据写入日常库。真实模型不需要为验证商品选择再发送用户资料。
