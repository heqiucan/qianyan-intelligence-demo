# V3：商品广告创作与投放助手

当前界面按用户确认保留原首页风格、紫色球体、四张指标卡和八个一级功能入口。V3 增强集中于“营销与创意”中的事实核对流程；四工作区方案已撤回，不再作为当前界面说明。

## 八个一级功能入口

| 入口 | 主要功能 |
|---|---|
| 增长工作台 | 原首页、统计卡片、活动策略、下一步和活动进度 |
| 商品与品牌 | 商品资料、图片、资料来源、版本保存 |
| 营销与创意 | 生成、编辑、事实核对、依据、修订对比、预览导出、素材版本 |
| 广告投放 | 计划、启动/暂停/结束、预算周期调整、模拟场景 |
| 效果与获客 | 成交、投放指标、客单价、数据范围和来源追溯 |
| 异常与待办 | 异常检查、依据查看和处理记录 |
| AI 优化复盘 | 复盘、调整草稿和观察记录 |
| 活动报告 | 报告快照、人工结论、打印导出 |

原路由、数据库和现有版本继续保留。新增事实核对、草稿保护、故障重试、工程拆分均保留。

## 主讲路线

1. 增长工作台创建活动，明确内部目标、受众假设、已知卖点和计划周期。
2. 营销与创意生成两组模板回放；选一份素材进行编辑。
3. 点击“载入核对示例”。它只把故意有问题的测试文案放进编辑区，不会自动保存。
4. 点击“核对当前文案”。服务端依据该素材保存的商品快照实际执行规则检查。
5. 对默认 99 元、500ml 的演示商品，示例中的 79 元、1L 分别提示冲突；保温 24 小时提示缺少依据。点击“查看依据”能看到字段、资料版本、原始资料出处与解释。
6. 查看修订建议的前后差异。采用建议只修改输入；仍可以继续编辑或放弃。
7. 重新核对，保存为新版本，再人工确认。确认接口会对已保存内容重新检查，不能借用此前的检查结果绕过校验。
8. 用当前素材创建投放草稿，核对预算和周期后启动模拟。
9. 体验广告预览、商品页、订单确认和模拟付款；进入效果与获客查看订单来源。
10. 选择同一范围形成优化建议、调整草稿和观察记录，最后保存活动报告快照。

从事实检查到计划的演示重点是：哪里有问题、依据是什么、如何修改、哪个版本被使用。没有伪造等待、随机进度或实时模型思考。

## 实际执行与模拟边界

- **实际执行**：商品与活动资料保存、价格/容量等支持范围内的规则检查、证据展示、素材版本、计划状态、现场测试订单、统计计算、报告快照和文件导出。
- **模板回放**：默认文案生成与复盘。仍只支持有限模板变化，不声称理解任意受众或营销指令。现有模型适配器保留，未配置密钥或调用付费模型。
- **模拟**：平台投放、预算消耗场景、付款、新老测试买家。没有接入抖音或 TikTok 广告账户，没有真实付款。
- **来源追溯**：本系统订单与计划、素材快照的显式关联；不等于平台广告归因或增量效果证明。

## 规则检查的边界

结果分为“与资料一致”“与资料冲突”“缺少依据”“需人工核查”。一致只代表与商家提供的素材快照一致，不表示资料已被独立认证。

规则覆盖带单位的数字价格、容量、部分时长和保证性表述。容量按升/毫升换算，0.5L 与 500ml 一致；脚本 0–3 秒时间轴不作为商品容量或价格。促销、比较、引用、否定、区间和组合等上下文保留人工核查，不自动把优惠价改成原价。

本轮不能解析所有中文语义，不能自动验证促销有效期、检测报告、商品性能、法律合规或平台过审。手工填入一段“证据”不会自动解除限制；存在待解决提示时需要修改为支持范围内的明确表达，再确认。

编辑后原检查结果失效；旧请求迟到不覆盖新的输入。失败保留输入并支持重试。建议仅针对可明确处理的片段，删除后仍须人工检查语句是否通顺。

## 数据解释

效果页优先显示支付金额、支付订单、识别新客和客单价，广告消耗、支付 ROI、点击率等保留在相应区域。客单价 = 同范围支付金额 / 支付订单数。支付金额不等于利润。

有效零值显示 0；缺少消耗显示“当前来源未提供”；缺少合法计算条件显示“暂不可计算”；加载失败显示失败和重试，不混为无数据。没有用少量模拟订单增加复购结论，也没有将订单/点击的比值冒充去重访客转化率。
