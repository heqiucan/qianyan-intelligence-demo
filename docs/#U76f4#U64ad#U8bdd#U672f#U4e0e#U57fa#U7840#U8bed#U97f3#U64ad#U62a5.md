# 直播话术与基础语音播报

## 使用流程

1. 进入直播工作台，创建场次并核对货盘。
2. 在“当前话术”中点击“编辑话术”，填写组名，新增话术，为每条选择主播或助播，然后保存。
3. 在“播报设置 → 音色库 / 主播与助播”中选择系统音色，设置语速、音量和句间停顿，保存。试听先生成 WAV，再点击播放器播放；可下载 WAV。
4. 点击“播报队列”，选已保存话术组，点击“准备播报队列”，再点击“开始播报”。
5. 使用暂停、继续、停止或跳过当前句控制语音。使用“临时插话”指定角色，并选择当前片段结束后插入或立即插入。
6. “运行日志”中分别查看模拟记录和语音播报记录。

## 真实边界

- 已实现：话术分组与条目编辑、排序、搜索、TXT/CSV 导入导出、版本保存、系统音色试听与 WAV 导出、主播助播分配、队列播放、暂停位置恢复、插播、屏蔽词、句间停顿、客户端播放日志。
- TXT 每行一条；CSV 使用 text、role 列，role 可填写 host/assistant 或 主播/助播。CSV 保留逗号和换行。导入仅追加编辑内容，保存后生效。
- Windows 系统音色在服务端合成，浏览器负责播放。优先使用可用的 PowerShell 7，回退到 Windows PowerShell；不同电脑实际可枚举音色可能不同。没有音色时显示错误，不伪造音色。
- 主播与助播的音色、语速和音量按队列快照固定。修改话术或设置后，需要明确准备新队列。旧队列不被改写。
- 全局屏蔽词跨场次共用。新增屏蔽词在每片段合成和开始播放前检查；命中则跳过整条话术。已经播放出去的声音不能撤回。
- 货盘未确认、商品版本过期或场次版本变化时阻止生成/开始下一段音频，要求更新货盘并重新准备队列。
- 手动填写的话术仍需运营者核实事实。尚未实现商品变量自动填充、AI 改写或自动事实审核。
- 暂停恢复依据 HTMLAudioElement 播放位置；立即插话可能需要等待首次语音合成，之后从原片段位置继续。句间停顿之外，首次合成/网络读取可能增加等待，不承诺无缝低延迟。
- 同场次切换面板保留编辑内容和队列；离开工作台、切换活动/场次会提示并停止声音。刷新仅恢复已保存内容，不自动出声，临时插话不会自动重放。
- 音色试听是独立播放器，开始试听会暂停队列；开始队列会暂停试听。
- 未实现：音色克隆、云端 TTS、麦克风插话、自动回复、自动客服、平台音频输出、全局音量闪避。Windows 系统音色不等于真人级音质。

## 实现与运行

- 后端：backend/speech/provider.py、sapi.ps1、routes.py。
- 前端：features/live/speech/ 下的编辑面板、播放器和导入导出工具。
- 数据复用 SQLite records 表，话术版本与队列快照只追加；删除话术组不删除已有队列。音频缓存位于独立数据目录的 speech-audio，按 provider/voice/rate/volume/text 哈希存储。
- 合成使用固定 PowerShell 脚本和 JSON 标准输入，用户文本不拼接进命令。固定脚本通过 EncodedCommand 运行，不修改系统执行策略。输出先写临时文件，校验 WAV 后原子替换。
- 音频合成串行限流，单次有超时，缓存上限 1 GB；音频请求沿用项目访问码校验。
- 此批开发使用 tmp/speech-dist 和 8042 独立测试服务；此前的 Cloudflare 分享未更新到这批版本。
- 可用 DEMO_FRONTEND_DIR 指定另一份前端构建；未设置时保持 frontend/dist。

## 验证

- TypeScript 与独立 Vite 构建通过。
- backend/test_speech.py、test_live_workspace.py、test_live.py：34 项通过。
- scripts/browser_live_speech.cjs：26 项真实 Windows 合成、浏览器播放、队列、插话、版本、导入导出与窄屏检查通过。
- scripts/run_e2e.py --speech：含语音和原有全套浏览器回归通过。非 Windows 或没有中文系统音色的机器请先跑普通回归，再单独核实语音环境。
- Windows 实测样例：中文主播 WAV 7.32 秒，首次合成约 0.92 秒；助播 WAV 4.23 秒，首次合成约 1 秒。这只是本机样例，不是性能保证。测试读取解码与播放事件，未把自动化播放成功当作主观音质评价。
- Motion product-ui 本地同源检查：CSS 无错误警告；TSX 为 99 分，提示按钮反馈在外部 CSS（已实现）。当前会话未加载 Motion MCP 工具，直接使用项目固定上游脚本。

## 参考与取舍

采用用户提供调研报告中的可插拔语音提供者、分段文件播放、内容哈希缓存和队列快照思路。System.Speech 使用本机已经安装的组件，不新增 TTS 库和模型。资料位置：Microsoft System.Speech SpeechSynthesizer.SetOutputToWaveFile 文档、dotnet/runtime 的 System.Speech 源码。本轮网络工具未返回可读的上游内容，实际可用性以本机生成 WAV 与播放测试为依据；没有直接采纳报告中未经复核的价格、许可和性能结论。

设计参考项目固定 Motion Site Builder product-ui / CoastSignal，主题和组件沿用项目。队列、插话、草稿保护、版本校验和缓存适配为本项目实现。
