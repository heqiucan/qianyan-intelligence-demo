# 六板块页面分级

确认来源：2026-11-26 用户批准六板块规划，要求清晰分级、按用户任务组织并使用紫色羽绒服商品样例。

## 页面层级

| 一级 | 二级 | 三级与操作 | 兼容入口 |
| --- | --- | --- | --- |
| 工作总览 | 今日工作、待办与审核、异常提醒 | 待办进入原内容/任务详情，处理记录不另复制 | overview、tasks |
| GEO 工作台 | 项目管理、问题监测、诊断优化、内容管理、效果报告 | 项目概况与关联资料、回答证据、内容独立编辑详情、报告 | geo?project=ID&view=... |
| 直播工作台 | 场次管理、现场控制、直播素材、场次复盘 | 明确选择场次后查看货盘/操作控制台；话术、媒体为当前场次的内容切换 | live、analytics?view=live、analytics?view=live-reports |
| 营销工作台 | 活动管理、需求与选题、内容创意、广告投放、效果与复盘、咨询助手 | 活动详情、需求任务、素材详情、投放计划、报告；保留医美公司看板与测试助手 | creative、agent?tab=demand、ads、analytics、overview?tab=assistant |
| 商品与知识 | 商品目录、品牌资料、知识资料 | 商品与 SKU 编辑、共享品牌事实、知识文档与草稿 | product、creative?tab=knowledge |
| Agent 中心 | 任务列表、新建任务 | 内容任务详情、运行步骤、审核产物、失败处理、返回来源 | agent（不含 tab=demand） |

URL 保持兼容，不因一级菜单合并改写已有业务数据。`workspaceNavigation.ts` 管理一级/二级归属与面包屑，`pages.ts` 仅补图标；旧路径正规化仍由 `navigation.ts` 管理。App 使用原页面键装配业务组件，不把“菜单所属模块”当作后端领域名。

## 交互约定

- 2026-11-26 用户最终确认：仅工作总览的“今日工作／待办与审核／异常提醒”显示为左侧子菜单，右侧不重复显示这一排导航。工作、业务运营、资产与执行三个分组保留；其余五板块仍使用原有右侧二级导航，不扩展左侧子菜单。

- 左侧固定六入口；二级导航在顶栏下吸顶，移动端换行显示。GEO 自带带项目上下文的二级导航。
- 详情保持一级高亮与返回入口。营销活动列表进入活动详情，GEO 默认项目列表，直播默认场次列表；不自动选中最后场次开启控制。
- 未选择直播场次时必须先选；返回场次列表不自动保留运行中媒体，仍经过未保存/播放保护。
- 品牌资料读取现有商品事实；当前无独立品牌后台。GEO 本地资料尚未与共享知识库打通，明确保持本地原型边界。
- 长内容编辑进入详情页；新增/确认等已有弹窗保留，不以层级调整擅自改动业务契约。
- 需求任务在营销工作台操作，Agent 中心仍是已有内容任务引擎；不宣称统一任务后台已经实现。

## 商品与预览

新数据库测试仍使用隔离虚构商品夹具。实际工作台必须读取用户已有商品与上传图片，不可因为“换样例”而切换为空演示库或用自绘图片替代。`backend/demo_product.py` 仅是初始化测试样例，不代表用户实际商品。商品资料页分基本资料、图片与视频、事实依据；目录的“关联素材”进入同商品活动，保留历史版本。

桌面原快捷方式继续调用 `scripts/start_geo.ps1`，8011 使用 `tmp/workspace-launcher.json` 中明确配置的既有数据库和本机环境文件；此文件及数据源标记均被 Git 忽略。未配置或数据库缺失时停止，不静默创建空库。配置切换前先做一致备份，并确认没有运行中任务；不自动停止未知端口进程。原 8010/旧演示数据库不清理，GEO v1 浏览器记录不清空。

侧栏按工作、业务运营、资产与执行分组，设置与帮助置底；顶栏固定在视口，二级导航在实测顶栏高度下吸顶。已保存内容的验证应在真实工作台只读进行；保存、审核、生成在隔离回放库验收，不对原资料自动写入。
